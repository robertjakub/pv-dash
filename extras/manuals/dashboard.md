# The dashboard manual

A single-page dashboard for home PV monitoring, fed by Prometheus: it serves
the page and proxies the upstream queries. Part of the pv-suite family.

- the daemon's own `--help` and the man page (`dashboard --man`) carry the
  startup surface; this page carries the full reference.

- **generated** from `lib/options.json` (the one-knob-one-source rows) by
  `dev/generators/manual.py` — edit the registry (or the REF data in the
  generator) and re-run, never this file.

## Run it

    python3 bin/dashboard.py                          # upstream http://localhost:9090
    python3 bin/dashboard.py --listen 127.0.0.1:8080 --upstream http://192.168.1.50:9090
    PROM_URL=http://pi:9090 python3 bin/dashboard.py  # via env
    # open http://localhost:8080

- the server **binds to `127.0.0.1:8080`** (loopback only) — pass `--listen 0.0.0.0:8080`
  to serve the LAN. The page and the proxy speak the family's F13 shape (the
  audit's F21): a **bearer token is mandatory beyond loopback** — a token-less
  non-loopback bind refuses to start. Set `--auth-token` (or `file:<path>`);
  the browser opens `http://host:8080/?auth=<token>` once — the exchange sets
  an HttpOnly session cookie — and scripts send `Authorization: Bearer <token>`.
  On the loopback bind the token is optional. Beyond localhost, still
  terminate TLS at an authenticating proxy (below).

- **static-only mode:** any web server works (`python3 -m http.server 8080 -d static`),
  but then set `prometheusUrl` in `config.js` to the direct Prometheus URL —
  the browser fetches it directly, which requires CORS to be allowed.

- the server's settings resolve CLI > env (the bare upper-snake twins:
  `LISTEN`, `PROM_URL`, `PROM_PREFIX`, `STATIC_DIR`, `CONFIG_JS`,
  `AUTH_TOKEN`, the caps, `LOG_ACCESS`, `CTL`, `CONTROL_TOKEN`, …) >
  `dashboard.conf` (the set grammar — every line a `set <name> <value>`; the
  bundled sample is `examples/dashboard.conf`) > defaults.

- `--prom-prefix ''` (empty) proxies *every* unmatched path to Prometheus. The
  HTTP surface carries the family's connection caps (`--max-clients`,
  `--max-conn-per-ip`, `--client-timeout`) — all live-settable through the
  control server.

## How it works

- **flow diagram** — live PV / Load / Grid nodes with animated energy
  particles (orange = solar, violet = grid import; speed and particle rate
  follow the power). Grid value is computed as **export − import** from the
  configured `gridExport` / `gridImport` metrics: **negative = import,
  positive = export**.

- **energy summary** — generated by PV, consumed by appliances,
  self-consumption vs fed-to-grid, with percentage bars, an energy table and a
  zoomable time-series chart. Energy (kWh) is integrated from
  `avg_over_time(<metric>[<step>s])` buckets, so every raw sample inside a
  bucket contributes — spikes are not lost; the step is always a multiple of
  `scrapeSec`.

- **auto-refresh** — selectable in the header (30 s / 1 min / 5 min / 30 min /
  custom); a switch refreshes the flow diagram, chart and table together.

- **CSV export** — energy in **watt-hours** (integrated from every Prometheus
  bucket in the period — same math as the table) for PV Yield, Home, Grid
  Export and Grid Import, zero-filled over the full period: hourly (day view),
  daily (month view), monthly (year view), per-year for "All time", plus an
  hourly detailed export for a whole month. ISO 8601 timestamps.

- **battery** — `battery: true` in `config.js` joins a Battery node to the
  flow diagram (teal particles: up = discharging, down = charging, a SoC %
  line), splits the energy three-way (PV / battery / grid) and adds the CSV
  columns. Without a working battery selector (missing metric or a constant
  `0`), the node dims and a warning banner appears.

- **theme** (dark / light / system) and **language** (EN / PL; add a language
  as `de: { ... }` in `i18n.js` — it appears in the switcher automatically) in
  the header, persisted in localStorage.

- if Prometheus is unreachable, the page switches to **DEMO DATA** so you can
  preview the layout.

## Speaking to the daemon

- the control server is a JSON-lines listener: a unix socket (the default
  `/tmp/dashboard-8080.socket`) or a TCP port on 127.0.0.1 — the
  `--control-port` flag, env `CTL`, `0` = off.

    python3 bin/dashboard-cli.py --control-port 15598 request reload-config
    python3 bin/dashboard-cli.py

- the one-shot spelling runs one command per invocation (or a batch on stdin).

- the **console** is the interactive session: `?` lists the words, TAB
  completes, `help <setting>` describes one, `help config` maps every knob to
  its control command, `show knobs` prints the dictionary.

- TCP control demands the token (`--control-token` / env `CONTROL_TOKEN`; the
  wire's `auth` verb carries it) and refuses to start without one; over the
  unix socket a trusted peer (root, the daemon's own user or
  `--control-trust-uids` — SO_PEERCRED) speaks without it.

- the optional ops token (`--control-ops-token`) scopes a session to the
  read-only verbs (the default: show). Every command is audited. The clients
  take `--control-port` (env `CTL`), `--timeout`, `--control-token`, the audit
  flags and `--man`; the cli adds `--reconnect` / `--reconnect-wait`.

- a knob's value resolves at start as flag > env > config script > default;
  the config file (the bundled `apps/dashboard/examples/dashboard.conf`)
  speaks the same grammar — `set <name> <value>` lines, `--dry-run` prints the
  effective settings.

The kinds — every row of the tables below carries one:

| kind | meaning |
|---|---|
| command | a one-shot action, no value |
| namespace | a word that groups deeper words: the console walk lists its children, `help <namespace>` describes them |
| settable | the knob is live: `set <name> <value>` applies at once (the flat registry name; the console also completes the row's live/alias path spellings and translates), `clear <name>` returns the configured value, `show <name>` prints the live value. *(restart)* — the set records a pending value and `request reload` applies it. *(secret)* — the value never renders back (show answers err); pass it by flag/env or as `file:<path>`. *(hidden)* — never lists in the ?/TAB pools; the wire still answers |
| startup-only | flag/env/config at start, a restart applies a change; the wire has no set/clear/show for it (it renders in `show config` only). Every secret is startup-only now (the tokens, the auth keys, the dump key): the wire refuses set/clear outright, the value passes by flag/env/config or as `file:<path>` and a restart applies it |
| show-only | a runtime report: `show <report>` answers, nothing to set |

## Commands

| command | kind | description |
|---|---|---|
| `help` | command (internal) | describe a word (help \<setting>) or map every knob (help config) |
| `inspect` | command | one pretty dump of everything (the state, the counters, the caps) |
| `ping` | command (internal) | keep-alive: answers pong |
| `quit` | command | close the session |
| `request` | namespace | the state machinery: the dump written and restored, the daemon reloaded |
| `request dump` | command (hidden) | write the state dump: the live setting overrides, sealed (when the daemon has a dump path) |
| `request reload` | command (hidden) | save the live overrides and restart the whole daemon (the config file and the flags are re-resolved) |
| `request reload-config` | command (hidden) | re-read the config file (the SIGHUP path) |
| `request restore` | command (hidden) | re-apply a state dump's overrides (when the daemon has a dump path) |
| `set` | command | configure a setting live: set \<setting> \<value> |
| `show` | command | print a setting's live value, or a report |
| `shutdown` | command | stop the server (asks to confirm) |
| `clear` | command | restore a setting to its configured value: clear \<setting> |

translate). The `default` column is the registry's built-in default (the
resolver's last rung after flag > env > config); the namespaces group them.

## Page configuration (config.js)

- all settings live in `config.js` (the shipped example is
  `examples/config.js`, served at `/config.js`; relocate with `--config-js`,
  `$CONFIG_JS` or `set config-js <file>` in `dashboard.conf` — if the override
  file is missing, `/config.js` 404s and the page boots with built-in
  defaults).

    const SOLAR_CONFIG = {
      prometheusUrl: '/prom',
      battery: true,
      metrics: {
        pv: 'huawei_pv_generation_watts{job="sun2000"}',
        gridExport: 'huawei_grid_export_watts{job="sun2000"}',
        gridImport: 'huawei_grid_import_watts{job="sun2000"}',
        load: 'huawei_home_consumption_watts{job="sun2000"}',
        battery: 'huawei_battery_net_watts{job="sun2000"}',
        batterySoC: 'huawei_battery_soc_percent{job="sun2000"}'
      },
      scrapeSec: 10,
      smoothMin: 30,
      refreshSec: 30,
      defaultLang: 'en',
      enableAllTime: false
    };

| key | meaning |
|---|---|
| `prometheusUrl` | `/prom` (the same-origin proxy) or a direct Prometheus URL |
| `metrics` | the full metric selectors — label matchers are passed through to PromQL; values always in **watts**. `gridExport` = export power (≥ 0); with `gridImport` set, the net grid value is `export − import` |
| `battery` | the battery panels' master switch (the selectors: `metrics.battery` signed W / `metrics.batterySoC` %; an optional `metrics.batteryFlag` present-flag for exporters that have one) |
| `scrapeSec` | the Prometheus scrape interval in seconds (bucket size) |
| `smoothMin` | display smoothing window in minutes (0 = raw) |
| `refreshSec` | the default auto-refresh interval (the header combo overrides; 0 = off) |
| `defaultLang` | the default UI language (`en`/`pl`) |
| `enableAllTime` | show the "All time" selector (for a long-retention backend); `?all` also works |
| `liveSec` / `chartSec` | the flow-diagram / chart-panel refresh intervals |

- URL params
  (`?prom=…&gridExport=…&grid=…&gridImport=…&pv=…&load=…&battery=1&batteryMetric=…&batterySoC=…&batteryFlag=…&scrape=…&smooth=…&refresh=…&lang=…&demoHour=…&consent=0`)
  override `config.js` for quick testing. `config.js` and `i18n.js` locations
  are configurable (`?config=<path>` / `?i18n=<path>`); a failed load falls
  back to the files next to the page, then to the built-in defaults.

## Behind a reverse proxy

- the dashboard only makes same-origin GET requests — any proxy works.

- **A. proxy → dashboard.py** (keeps Prometheus hidden): run `bin/dashboard.py --listen 127.0.0.1:8080`
  so only the proxy reaches it.

    location / { proxy_pass http://127.0.0.1:8080; }   # nginx

    solar.example.com { reverse_proxy 127.0.0.1:8080 }  # Caddy

- **B. the proxy serves the static files and routes `/prom` to Prometheus
  itself:**

    root /var/www/dashboard;
    location /prom/ { proxy_pass http://127.0.0.1:9090/; }  # trailing slash strips prefix

- `prometheusUrl: '/prom'` works in both cases. Mount at the root (or strip
  the prefix); add auth at the proxy if exposed to the internet.

## Metrics source

- the page expects PV inverter metrics in Prometheus (`huawei_*_watts` — the
  scraper's `--metrics-prefix` default). The `scraper/` subproject ships a
  dependency-free Python exporter that polls the inverter over Modbus TCP and
  serves exactly those metrics — see `../scraper/README.md`.

    python3 apps/scraper/bin/modbus-scraper.py --upstream <inverter-lan-ip>:502 --listen 0.0.0.0:9350

    # prometheus.yml — the job name must be "sun2000" (the dashboard filters on it)
    scrape_configs:
      - job_name: sun2000
        scrape_interval: 10s          # match scrapeSec in config.js
        static_configs:
          - targets: ['localhost:9350']

- the inverter accepts only one Modbus TCP client — the `cache/` subproject is
  an **experimental** caching proxy that multiplexes that one connection so
  the scraper can share it with other tools (`../cache/README.md`).

## Testing

- the dashboard profile rides the battery runner; the `/config.js` fuzz pin
  rides the same suite (a bogus override file must not crash the server). The
  scenario must end with the server alive and **zero tracebacks** in the logs.

    dev/battery/battery.py dashboard             # the dashboard profile: the control fuzz +
                                           #   the audit chain (the suites refuse without
                                           #   the runner's PV_RUN_DIR)

The ?/TAB pools, `show knobs` and `help config` all render from the same
rows this page was generated from.
